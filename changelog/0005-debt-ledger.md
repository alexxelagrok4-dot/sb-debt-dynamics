# 0005 — Аналитический накопитель долга

**Дата:** 2026-08-03

## Что изменилось
Долг перестал быть разовым числом из отчёта 1С и стал накопителем, который ведёт сама программа:

- старт — факт долга и остатка аванса 1С на дату первого появления контрагента;
- каждый выставленный через журнал «Счёт на продление» (суточный платёж × число дней по счёту) сначала гасится из остатка аванса, а нехватка уходит в долг;
- «Подтверждение оплаты получено» — с ручным вводом суммы, уменьшает именно накопленный долг;
- новые действия «Взыскано (сумма получена)» и «Возврат оборудования (тоннаж зафиксирован)» — со своими числовыми полями, ведут отдельную накопительную статистику (сколько всего взыскано/возвращено), не завязанную на текущий остаток долга;
- журнал действий переведён с выпадающего списка на чекбоксы — можно отметить сразу несколько действий одной датой (например, счёт + претензия + начато изъятие), без привязки к текущей стадии — начальник СБ может действовать с упреждением;
- в карточке контрагента — сводка: долг (накоплено), остаток аванса, суточный платёж, дата последнего учтённого периода, взыскано всего, возвращено тоннажа всего;
- добавлена защита: приложение не даёт выставить счёт с датой раньше уже учтённого периода.

## Зачем
1С показывает факт долга только на дату отчёта и часто пуст на ранних стадиях (клиент ещё проедает аванс) — при этом отдел уже должен действовать. Только по данным самого отчёта плановые показатели по отделам 0-7/8-14/15-21/22-28 показывали 0 ₽ там, где риск был реальным.
