# 0001 — Первая версия инструмента

**Дата:** 2026-08-03

## Что изменилось
Инструмент создан с нуля на основе анализа 4 реальных выгрузок из 1С (отчёт СБ и файл «Динамика СБ» на 27.07 и 03.08). Загрузка одного еженедельного файла «отчёт СБ»:

- классифицирует каждого контрагента по стадии просрочки, читая готовые бакет-колонки 1С (0-7 / 8-14 / 15-21 / 22-28 / 29+), не пересчитывая пороги самостоятельно;
- сравнивает с предыдущей загрузкой и показывает динамику: кто ухудшился, улучшился, новый или выбыл из просрочки;
- сопоставляет контрагентов по названию без учёта содержимого скобок (там указан закреплённый менеджер, который может меняться неделя к неделе для того же клиента) — проверено на реальных данных: без этого правила 18 «выбывших» + 14 «новых», с правилом — 16 и 12 (верные цифры);
- показывает плановые показатели по отделам на период (сумма к сбору на этапе продления, ожидающие претензии, тоннаж к изъятию, долг к взысканию через суд) — считается из данных, не вводится вручную;
- показывает конверсию по стадиям: что случилось с теми, кто был в каждой стадии на прошлой загрузке;
- ведёт журнал действий по каждому контрагенту (звонок, претензия, изъятие, суд) с датой и автором.

## Зачем
Служебной команде было неудобно вручную сверять две громоздкие таблицы 1С неделя к неделе, чтобы понять, кто перешёл в более серьёзную стадию просрочки и по кому уже нужно новое действие.
