# ПРОДЛЕНИЕ-ВЗЫСКАНИЕ

Внутренний инструмент для службы безопасности: раз в неделю загружается файл «отчёт СБ» (выгрузка из 1С), инструмент сам:

- классифицирует каждого контрагента по стадии просрочки (0–7 / 8–14 / 15–21 / 22–28 / 29+ дней) — по тем же данным, что уже проставлены в файле;
- сравнивает с выбранным периодом (по умолчанию — предыдущей загрузкой, но период сравнения можно выбрать вручную) и показывает динамику: кто ухудшился, кто улучшился/погасил долг, кто новый, кто выбыл из просрочки;
- ведёт накопительный долг по каждому контрагенту (аналитический накопитель, а не разовая выгрузка из 1С): старт — факт. долг (см. ниже) и аванс 1С на дату первого появления контрагента; дальше каждый выставленный счёт на продление (суточный платёж × дни по счёту) сначала гасится из остатка аванса, а нехватка уходит в долг; ручные оплаты и взыскания по суду уменьшают долг; возврат оборудования (тоннаж) фиксируется отдельно;
- отдельным инструментом — независимым от стадий, KPI и динамики — считает **прогноз долга на произвольную будущую дату** (по умолчанию конец текущего месяца) по всем контрагентам с долгом или оборудованием на руках;
- автоматически подсвечивает несостыковки между загрузками (аномалии — резкие скачки платежа/тоннажа/стадии) в комментариях в приложении;
- показывает плановые показатели по отделам на период (сколько собрать на этапе звонков, кому выставить претензии, сколько тонн изъять, сколько взыскать через суд, сколько уже взыскано/возвращено) — считается из данных, не вводится вручную;
- показывает состав портфеля по стадиям на текущую загрузку и динамику долга/тоннажа за период с разбивкой «новый долг / погашено-выбыло / изменение у продолжающих» (без задвоения одного и того же перехода как «минус в одной стадии, плюс в другой») — везде можно кликнуть и провалиться в список конкретных контрагентов;
- подсвечивает контрагентов, по которым не произведено ожидаемое для их стадии действие, с фильтром «только без действия» по каждой зоне ответственности (продление / претензии / изъятие / взыскание);
- ведёт журнал произведённых действий по каждому контрагенту (звонок, претензия, счёт на продление, оплата, изъятие, суд, взыскание, возврат оборудования) с датой и автором — можно отмечать несколько действий сразу.

Файл `index.html` — самодостаточный (весь код внутри, никаких серверных компонентов кроме Supabase для хранения данных и входа). Открывается в любом браузере.

## Вход

Тот же логин/пароль, что и в остальных внутренних инструментах компании (Supabase-проект общий, вход по логину без почты). Полная инструкция для сотрудников — от регистрации до ежедневной работы: **https://alexxelagrok4-dot.github.io/sb-debt-dynamics/instructions.html** (или [`instructions.md`](instructions.md) в виде обычного текста).

## Структура данных 1С-отчёта, которую ожидает инструмент

Первый лист файла, первая строка — заголовки, далее по одной строке на контрагента:

`Клиент | Кол-во дней после закрытия периода | Задолженность | Авансы | Залог | Стоимость оборудования | Суточный платёж | Прогноз задолженности | Вес у клиента (кг) | Дней просрочки | 0-7 | 8-14 | 15-21 | 22-28 | 29+`

Есть переключатель логики стадий: «календарная» берёт готовые 5 колонок 1С как есть (дни с конца оплаченного периода), «по деньгам» (по умолчанию) — считает стадию от накопленного долга после исчерпания аванса, в днях суточного платежа, не эскалируя контрагентов, у которых ещё есть прикрытие авансом. См. [changelog 0008-0009](changelog/0008-debt-based-stage-classification.md).

**«Задолженность» ≠ факт. долг.** По устройству исходной таблицы «Задолженность» — это ожидаемый долг за **будущий** период по условиям предоплаты (оплата вносится за 5 дней до начала нового периода; если её нет — контрагент уже виден как должник, хотя может вернуть оборудование, не начав толком новый период), а не факт за уже потреблённые дни. Настоящий факт. долг на дату отчёта = «Прогноз задолженности» (пересчитывается 1С заново из аванса и суточного платежа) за вычетом остатка аванса — именно он используется в денежной классификации, накопителе и во всех суммах приложения. «Задолженность» показывается только справочно в карточке контрагента. См. [changelog 0011](changelog/0011-factual-debt-and-forecast-tool.md).

**Важный нюанс сопоставления контрагентов между неделями:** в скобках у имени контрагента указан закреплённый менеджер — он может меняться от недели к неделе у того же самого контрагента. Инструмент сопоставляет контрагентов по названию **без учёта содержимого скобок**, поэтому смена менеджера не считается «новым»/«выбывшим» клиентом.

## Передача партнёру / независимая копия

Репозиторий публичный — код можно свободно клонировать, форкнуть или скачать по ссылке выше без каких-либо действий с этой стороны. Если нужна **полностью независимая копия со своими данными** (не общая база с текущими пользователями) — пошаговая инструкция по своему Supabase-проекту: [`independent-copy-setup.md`](independent-copy-setup.md).

## Планы на будущее

Данные (таблицы `sb_uploads`, `sb_snapshots`, `sb_actions` в Supabase) спроектированы так, чтобы их можно было позже перенести в интеграционную систему DAYA — модель данных простая и привязана к названию контрагента, без специфичных для этого инструмента допущений.
