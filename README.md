# СБ — динамика просрочки

Внутренний инструмент для службы безопасности: раз в неделю загружается файл «отчёт СБ» (выгрузка из 1С), инструмент сам:

- классифицирует каждого контрагента по стадии просрочки (0–7 / 8–14 / 15–21 / 22–28 / 29+ дней) — по тем же данным, что уже проставлены в файле;
- сравнивает с предыдущей загрузкой и показывает динамику: кто ухудшился (перешёл в более серьёзную стадию), кто улучшился/погасил долг, кто новый, кто выбыл из просрочки;
- показывает плановые показатели по отделам на период (сколько собрать на этапе звонков, кому выставить претензии, сколько тонн изъять, сколько взыскать через суд) — считается из данных, не вводится вручную;
- показывает конверсию по стадиям (эффективность): что случилось с теми, кто был в каждой стадии на прошлой загрузке;
- ведёт журнал произведённых действий по каждому контрагенту (звонок, претензия, изъятие, суд) с датой и автором.

Файл `index.html` — самодостаточный (весь код внутри, никаких серверных компонентов кроме Supabase для хранения данных и входа). Открывается в любом браузере.

## Вход

Тот же логин/пароль, что и в остальных внутренних инструментах компании (Supabase-проект общий). Вход по логину без почты — см. инструкцию.

## Структура данных 1С-отчёта, которую ожидает инструмент

Первый лист файла, первая строка — заголовки, далее по одной строке на контрагента:

`Клиент | ... | Задолженность | Авансы | Залог | Стоимость оборудования | Суточный платёж | Прогноз задолженности | Вес у клиента (кг) | Дней просрочки | 0-7 | 8-14 | 15-21 | 22-28 | 29+`

Стадия определяется по тому, в какой из последних 5 колонок стоит значение (как это уже делает сама выгрузка 1С) — инструмент не пересчитывает эти пороги самостоятельно.

**Важный нюанс сопоставления контрагентов между неделями:** в скобках у имени контрагента указан закреплённый менеджер — он может меняться от недели к неделе у того же самого контрагента. Инструмент сопоставляет контрагентов по названию **без учёта содержимого скобок**, поэтому смена менеджера не считается «новым»/«выбывшим» клиентом.

## Планы на будущее

Спроектировано так, чтобы данные (таблицы `sb_uploads`, `sb_snapshots`, `sb_actions` в Supabase) можно было позже перенести в интеграционную систему DAYA — модель данных простая и привязана к названию контрагента, без специфичных для этого инструмента допущений.
