# Инструкция — ПРОДЛЕНИЕ-ВЗЫСКАНИЕ

Ссылка на инструмент: **https://alexxelagrok4-dot.github.io/sb-debt-dynamics/**

Открывается в любом браузере (Chrome, Edge, Safari), ничего устанавливать не нужно. Вход — по логину и паролю, почта не нужна и не используется для самого входа. Данные общие для всей службы безопасности — все сотрудники с доступом видят одни и те же загрузки, долги и журналы действий.

## Первый раз: регистрация

1. Откройте ссылку выше.
2. В поле **Логин** укажите логин латиницей, без пробелов. Рекомендуем использовать часть вашей рабочей почты **до знака @dayagroup.ru** — например, если ваша почта `ivanov@dayagroup.ru`, логином укажите `ivanov`. Это не обязательно технически, но так логины сотрудников легко узнаваемы в общих списках и журналах.
3. В поле **Пароль** придумайте пароль (минимум 6 символов) и запомните его.
4. Нажмите **Зарегистрироваться**.
5. Готово — сразу нажмите **Войти** с теми же логином и паролем. Никаких писем и подтверждений не требуется (реальная почта, включая dayagroup.ru, здесь не задействована — см. раздел для администратора).

**Логин нельзя восстановить самостоятельно, если забыли, что вводили** — записывайте его так же, как пароль. Если логин уже занят кем-то другим — при регистрации появится сообщение об этом, попробуйте другой (например, добавьте первую букву фамилии).

## Обычный вход

1. Откройте ссылку.
2. Введите **Логин** и **Пароль**.
3. Нажмите **Войти**.

## Забыли пароль

Самостоятельно сбросить пароль нельзя — обратитесь к администратору. Он сбросит пароль напрямую в панели управления (раздел «Для администратора» ниже) и сообщит новый пароль любым удобным способом.

## Еженедельная загрузка отчёта

1. В карточке **«Загрузка отчёта»** нажмите на поле файла и выберите файл выгрузки из 1С («отчёт СБ», формат .xlsx).
2. Укажите **дату отчёта** — за какое число выгрузка.
3. Нажмите **«Загрузить и обработать»**.

Программа сама разберёт файл и построит динамику относительно предыдущей загрузки. Если файл не похож на нужный экспорт (не тот файл, повреждён, не тот лист) — появится понятное сообщение об ошибке вместо частично загруженных данных.

## Выбор периода и с чем сравнивать

Карточка **«Период»**:

- **«Показать динамику на дату»** — какую загрузку сейчас смотреть (по умолчанию — самая свежая).
- **«Сравнить с периодом»** — с какой более ранней загрузкой сравнивать. По умолчанию — предыдущая по хронологии, но можно вручную выбрать любую другую, если нужно сопоставить не с прошлой неделей, а, например, с позапрошлой.
- **«Логика стадий»** — как именно определяется стадия просрочки 0-7/8-14/15-21/22-28/29+ у контрагента:
  - **По деньгам** (по умолчанию) — стадия считается от реально накопленного долга после того, как у клиента исчерпан аванс, в днях суточного платежа. Контрагент с большим остатком аванса не считается «в изъятии», даже если календарно 1С уже отсчитала много дней с конца периода.
  - **Календарная (1С/«Динамика СБ»)** — прежняя логика 1С, дни считаются от даты окончания оплаченного периода напрямую, без учёта аванса. Совпадает с официальным файлом «Динамика СБ».

  Переключается мгновенно и сразу пересчитывает все таблицы и показатели ниже — можно сверять обе картины.

## Таблица «Контрагенты в просрочке»

- **Поиск по названию** — фильтр по имени контрагента.
- **«Только ухудшившиеся»** — показывает только тех, кто за этот переход перешёл в более серьёзную стадию.
- **«Только без нужного действия»** — показывает только тех, по кому ещё не зафиксировано ожидаемое для их стадии действие (см. ниже).
- Фильтр по стадии — сузить до конкретной стадии 0-7/8-14/15-21/22-28/29+.

Строки, где по контрагенту не зафиксировано ожидаемое действие, подсвечены и помечены бейджем «Действие не зафиксировано». По каждой стадии/зоне ожидается своё действие:

| Зона | Ожидаемое действие |
|---|---|
| Продление (до просрочки) | Счёт на продление выставлен / Подтверждено: возврат без продления |
| 0–7 дней | Звонок/переговоры / Подтверждение оплаты получено |
| 8–14 дней | Претензия направлена |
| 15–21 и 22–28 дней | Изъятие начато / Изъятие завершено |
| 29+ дней | Передано в суд/банкротство / Взыскано / Возврат оборудования |

## Журнал действий по контрагенту

Кнопка **«Журнал»** в строке контрагента открывает карточку с историей действий и сводкой по долгу (накопленный долг, остаток аванса, суточный платёж, дата последнего учтённого периода, взыскано и возвращено всего).

Ниже — форма для новой записи. Можно отметить сразу **несколько действий одновременно** одной датой (например, счёт на продление и претензию вместе):

- **Счёт на продление выставлен** — при отметке появляется поле «Оплачен по дату»: укажите дату, по которую выставлен счёт. Отдельная «дата действия» в этом случае не нужна — используется дата счёта. Сумма к долгу считается автоматически (суточный платёж × число дней), сначала гасится из остатка аванса.
- **Подтверждено: возврат без продления** — контрагент подтвердил, что не продлевает аренду; исключается из плановых показателей отделов как ожидаемое, а не проблемное, завершение.
- **Подтверждение оплаты получено** — требует указать сумму оплаты вручную; уменьшает накопленный долг на эту сумму.
- **Взыскано (сумма получена)** — сумма, взысканная через суд/претензионную работу; уменьшает долг и добавляется в статистику «взыскано всего».
- **Возврат оборудования (тоннаж зафиксирован)** — тоннаж, фактически возвращённый/изъятый; добавляется в статистику «возвращено тоннажа всего», на долг не влияет.
- Остальные действия (звонок, претензия, изъятие начато/завершено, передано в суд, прочее) — фиксируются с общей датой действия и необязательным комментарием.

Приложение не даст выставить счёт с датой раньше уже учтённого периода — если такое происходит, проверьте дату.

## Плановые показатели по отделам

Считаются автоматически из текущих данных (не вводятся вручную): сколько нужно собрать на этапе продления, сколько претензий ещё не направлено, сколько тонн нужно изъять, сколько денег и тоннажа под риском на стадии суда/взыскания — и сколько уже фактически взыскано/возвращено.

## Погашено / выбыло из просрочки

Таблица внизу — контрагенты, которые полностью пропали из отчёта с прошлой загрузки (расторжение, полное закрытие).

Кнопка **«Показать частичные погашения»** разворачивает отдельный список: контрагенты, которые остались в отчёте, но у которых снизился долг и/или просроченный тоннаж за этот переход — «долг уменьшился на X, осталось Y» или «долг полностью погашен». Показывается только сама перемена — если долг уже был закрыт раньше и с тех пор ничего не изменилось, повторно не появится.

## Автоматические замечания

Кнопка **«Показать замечания»** в верхней части (если она есть — появляется только когда есть что показать) разворачивает список несостыковок между этой и прошлой загрузкой: резкий скачок платежа/тоннажа, скачок сразу через несколько стадий, похожие названия в одной загрузке. Это не ошибки сами по себе, а повод перепроверить конкретного контрагента.

## Если что-то не работает

| Проблема | Что делать |
|---|---|
| «Такой логин уже занят» при регистрации | Кто-то уже зарегистрировал этот логин — попробуйте другой. |
| «Неверный логин или пароль» при входе | Проверьте логин и пароль (с учётом регистра). Если не помните — см. «Забыли пароль». |
| «Файл не похож на «отчёт СБ»» при загрузке | Выбран не тот файл — нужен именно еженедельный «отчёт СБ» из 1С, не файл «Динамика СБ» и не какой-либо другой отчёт. |
| Не могу выставить счёт — «дата счёта должна быть позже уже учтённого периода» | Укажите дату дальше уже зафиксированной в сводке по контрагенту («Оплачен период по»). |
| Долг контрагента показывает 0, хотя должен быть больше | Проверьте переключатель «Логика стадий» — в денежном режиме контрагент с ещё не исчерпанным авансом законно показывает 0; в календарном режиме сверьте с колонкой «Задолженность» в самом файле 1С. |
| Не вижу нужного контрагента в таблице | Проверьте фильтры (поиск, «только ухудшившиеся», «только без действия», стадия) — возможно, он скрыт одним из них. |

## Для администратора: сброс пароля сотруднику

1. Зайдите на **supabase.com** → откройте проект.
2. **Authentication → Users**.
3. Найдите нужного сотрудника — его логин `ivanov` виден в списке как `ivanov@opalubka.invalid` (служебный технический адрес; реальная почта, включая корпоративный домен dayagroup.ru, здесь не используется — на него ничего не приходит и не должно).
4. Откройте пользователя → задайте новый пароль через действие сброса/установки пароля в интерфейсе Supabase.
5. Сообщите сотруднику новый пароль любым удобным способом.

Тем же способом можно заблокировать или удалить доступ сотруднику, который покинул компанию.

## Для администратора: где что хранится

- Все данные (загрузки, снэпшоты по контрагентам, журнал действий) — в Supabase-проекте, общем с другими внутренними инструментами компании.
- Список всех сделанных изменений в самом инструменте — в папке `changelog/` рядом с файлом инструмента (каждое изменение отдельным файлом, в хронологическом порядке).
